# 并行执行

## 准入判断

仅当任务包含两个以上独立可执行问题（只读任务优先使用并行），且并行收益高于派发、协调和汇合成本时并行。一个问题只有同时满足以下条件才视为独立：

- 目标和输出可单独验收，输入、依赖及 API/类型契约已经确定。
- 不依赖另一问题尚未产生的结论或修改，执行顺序不影响结果。
- 写入范围不重叠，不共享可变状态、运行环境或互斥资源。

任一条件不确定时先串行调查；不得为了使用多 Agent 人为拆分任务。

## 任务拆分

1. **从验收倒推**：每个子任务只承担一个可独立验收的结果；同一结果的高度耦合修改保留在一个任务内。
2. **标出依赖**：列明输入、前置结论和下游消费者。存在 `A -> B` 时串行；依赖图中无路径相连或处于同一无依赖层的任务才可并行。
3. **冻结共享契约**：API、类型、数据结构、交互或共享配置未确定时先串行确认，禁止下游各自假设；冻结后才能按独立写入范围并行。
4. **划定所有权**：指定目标路径、可修改范围和禁止事项。写入重叠时合并或串行；同一文件的不同区域不算独立。
5. **定义输出契约**：写明目标、依赖、文件范围、输出、验收、禁止事项和前置任务，并满足全局子任务移交要求。
6. **控制粒度**：任务应可独立实现、验证和评审，目标在 40 分钟内完成。协调成本更高时合并；包含多个结果或预计超时则继续拆分。

先执行公共契约和共享基础任务，再并行执行无依赖任务，最后由主 Agent 串行检查冲突并整体验证。依赖前序产物的调查、实现和评审属于流水线，不算并行。

## 流程选择

- 派发前先读取当前流程预算。自动模式先确定当前任务档位；轻量级、中量级和重量级分别服从各自累计派发配额。Superpowers 生成或更新设计、计划、任务清单或失败分组后，以及选择执行 Skill 或派发前，必须重新进入本规则。
- 强制流程 Skill 可先运行；其生成或更新设计、计划、任务清单、失败分组后，以及选择执行 Skill 或派发前，主 Agent 须重建依赖层。`writing-plans` 后不得直接接受默认交接：两个以上无依赖任务用 `dispatching-parallel-agents` 同轮派发，否则串行使用 SDD 或 `executing-plans`。
- 已有实施计划时，可使用 `superpowers:subagent-driven-development` 管理实现和评审；必须遵循其原生流程，串行派发单个实施 Agent 及其评审 Agent，严禁同时派发多个实施 Agent。
- 确需并行写入时不得使用 `subagent-driven-development`；只有共享契约已冻结、写入路径互斥且运行环境隔离时，才可通过 `dispatching-parallel-agents` 派发。
- SDD 可按全局 Git 规则创建范围明确的普通本地提交，但不得 amend、改写历史或推送。
- 调用 `superpowers:using-git-worktrees` 前，须通过 HITL 逐项说明 Worktree 创建、`.gitignore` 或项目设置修改及其提交、依赖安装与生命周期脚本、lockfile 或构建生成物变化、服务启动和基线测试；必要步骤未获授权时不得启动该 Skill。
- 相关 Skill 不可用时遵循全局能力恢复；恢复失败后改为串行，不以手工并发绕过。

## 禁止并行

- 后一任务依赖前一任务输出，或多个现象可能来自同一根因。
- 修改同一文件、共享生成物、公共接口尚未确定，或需要持续同步设计决策。
- Editor MCP 写入、场景或资源修改；只读查询也须确保连接和状态稳定。
- 数据迁移，以及 Git 暂存、拉取、合并、提交等会改变共享状态的操作。
- 共用开发服务器、端口、数据库、缓存、构建目录或其他互斥资源。
- 正在等待 HITL Checkpoint，或当前任务的派发成本高于直接处理。

## 派发约束

- 子任务和累计派发数量服从当前流程预算；评审或修复 Agent 按其只读或可读写身份计入对应配额，同时活动数量仍受平台并发上限约束。
- 只读 Micro-Agent 沿用 `[MICRO-TASK]` 模板；写入子任务还须满足全局子任务移交要求，并明确依赖、写入范围、输出契约、验收条件及适用的 Git、HITL 和禁止扩大范围条款。
- 子 Agent 不得扩大范围、修改共享契约、自行集成或再次派发。需要超出范围时只报告，由主 Agent 决定后续流程。

## 汇合与降级

- 主 Agent 汇合前必须比较实际变更路径、声明范围和用户授权范围，并确认共享契约未被擅自修改；不匹配时拒绝集成并报告。
- 主 Agent 负责复核证据、检查冲突，按依赖顺序集成，并执行最小充分的整体验证。
- 执行中发现新依赖、范围重叠或共享状态时，立即停止相关并行写入，保留已完成结果并改为串行。
