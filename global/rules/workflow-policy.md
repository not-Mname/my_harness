# Workflow 流程预算策略

## 使用方式

- 新对话默认进入自动模式；自动模式在每个任务开始时重新判断轻量级、中量级或重量级。
- `$workflow-light`、`$workflow-medium`、`$workflow-heavy` 将当前对话持续锁定到固定模式；`$workflow-auto` 恢复逐任务判断。
- 自动判定只对当前任务生效，不改变对话的持续状态；固定模式不根据任务复杂度自动升降级。
- 模式指令携带任务正文时，先切换再执行；没有任务正文时只确认切换结果。最新显式切换优先，任务中途切换只影响未完成步骤。

## 模式预算

| 维度 | 轻量级 | 中量级 | 重量级 |
|---|---|---|---|
| 核心目标 | 速度优先 | 速度与质量平衡 | 完整性优先 |
| 可读写 Agent | 每任务累计最多 1 个 | 每任务累计最多 3 个 | Harness 不限制 |
| 只读 Agent | 每任务累计最多 3 个 | 每任务累计最多 5 个 | Harness 不限制 |
| 测试轮次 | 每任务最多 1 次 | 每任务最多 3 次 | Harness 不限制 |
| 澄清轮次 | 每任务最多 3 次 | 每任务最多 5 次 | Harness 不限制 |

配额必须在任务开始时用于规划流程、选择验证目标和安排 Agent，不得先机械执行完整流程，再以配额耗尽为由停止。

## 流程裁剪

### 轻量级

- 读取最少必要上下文后直接处理；将 `brainstorming` 压缩为必要澄清和简短方案确认。
- 默认不生成持久化规格或实施计划；复杂任务只维护简短任务清单。
- 不强制 TDD；将唯一测试轮次用于信息量最高的验证。
- 主 Agent 检查 diff，不强制派发评审 Agent。
- 最终只报告变更、验证证据和残余风险。

### 中量级

- 合并需求澄清、方案比较和关键设计确认，避免逐项往返。
- 多文件、跨模块或存在关键契约时生成规格；多步骤任务生成可压缩的实施计划。
- 高风险逻辑优先 TDD，其余按风险选择；重要修改至少进行一次定向评审。
- 最终报告变更、验证、评审和风险。

### 重量级

- 完整执行所有适用的 Superpowers 流程，不设置 Harness 数量限制。
- 不机械调用无关 Skill，也不突破平台并发、上下文容量或更高优先级规则。

## 计数口径

### Agent

- 配额按单任务累计派发量计算；完成、失败、中断和返工派发均占用额度。
- 派发时冻结只读或可读写身份，只读 Agent 不得升级为可读写 Agent。
- 子 Agent 不得继续派发。平台并发上限独立生效。

### 测试

- 一轮只能运行一个既有测试目标；允许测试框架内部执行多个用例，不得临时组合独立目标规避配额。
- 修复后重新运行计为新测试轮次。
- lint、类型检查、构建和测试框架执行计入测试轮次；`git diff`、只读搜索和纯静态内容检查不计入。
- 因工具、依赖或环境故障而未真正开始验证的调用不消耗额度，但必须保留失败证据。

### 澄清

- 每次暂停并等待用户补充需求、范围或技术歧义，计为一轮。
- 合并相关问题，采用有依据的低影响假设并尽早执行；不能机械走完完整流程后再以额度不足停止。
- 法律、安全、数据、外部副作用、Git 历史改写和 Editor MCP 等强制 HITL 不计入普通澄清轮次，也不得因配额耗尽而跳过。

## 自动路由

按重量级条件优先、轻量级条件全部满足、其余默认中量级的顺序判断，不使用数字评分。

### 轻量级条件

仅在以下条件全部满足时选择轻量级：

- 目标明确，关键契约没有待确认项。
- 属于只读查询、解释、翻译、局部文档调整或范围明确的低风险修改。
- 修改范围局部，预计一次高价值验证足够。
- 不涉及安全、数据迁移、公共 API、共享基础设施、项目设置或显著外部副作用。
- 不需要完整规格、跨模块协调或多轮评审。

### 重量级条件

命中以下任一条件即选择重量级：

- 架构设计、跨模块重构或公共契约变更。
- 数据迁移、鉴权、安全、隐私、支付或不可逆外部副作用。
- Cocos、Unity 场景、资源或项目设置等需要严格 Editor MCP 流程的高风险修改。
- 任务包含多个相互依赖的子系统，或预计需要持续多轮实现与评审。
- 用户明确要求完整 Superpowers、完整 TDD、全面评审或最高可靠性。
- 中量级预算明显不足以完成必要验证。
- 失败可能造成严重的数据、生产或兼容性影响。

### 中量级条件

未命中重量级条件，也不同时满足全部轻量级条件时选择中量级。常见任务包括常规功能开发、一般 Bug 修复、多文件但边界清晰的修改，以及需要有限设计、计划、测试或评审的任务。

### 判定与升级

- 每个自动任务开始时输出 `[自动模式 -> 档位]` 和一句核心理由，随后立即执行，不请求批准。
- 轻量级发现公共契约、跨模块影响或第二轮必要测试时，可以升级到中量级。
- 轻量级或中量级发现重量级风险时，可以升级到重量级。
- 自动升级必须告知用户，不得自动降级；升级前已消耗的 Agent、测试和澄清轮次计入新档位。
- 手动固定模式不自动升级；只有不可绕过底线冲突时才进入 HITL。

## 规则优先级

1. 系统、平台、安全、数据、外部副作用和强制 HITL 规则。
2. 用户在当前任务中明确提出的执行要求或显式指定的 Skill。
3. 用户手动锁定的固定模式。
4. 自动模式为当前任务选择的临时档位。
5. Superpowers Skill 自身的默认完整流程。
6. Harness 的一般效率偏好。

用户显式要求的 Skill 必须执行。必要步骤超过当前档位配额时，只放宽与该 Skill 直接相关的预算并简短声明，不改变对话的持续模式。

## 异常处理

- 工具、连接、依赖或环境故障遵循全局能力恢复规则；未真正启动的测试不消耗轮次，实际运行但失败的测试消耗轮次。
- 自动模式预算不足时按路由规则升级；手动固定模式发现范围扩大时重新规划剩余预算，不自动升级。
- 固定模式无法覆盖普通质量目标时，完成可安全完成的范围并明确残余风险，不得只以配额不足为由停止。
- 只有继续执行会违反不可绕过底线时，才通过 HITL 请求切换模式、缩小范围或停止。
