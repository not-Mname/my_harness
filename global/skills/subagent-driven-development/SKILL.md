# 子智能体驱动开发（Harness 裁剪版）

本技能是插件 `superpowers-zh:subagent-driven-development` 的 harness 门禁版。完整流程、提示词模板与脚本参考插件原版；**配额与串行约束以本文件为准**。

## 门禁

1. 派发前读取 `~/.codex/rules/workflow-policy.md` 与 `~/.codex/rules/multi-agent-assistance.md`，确认档位预算：轻量级一般不使用本技能（可读写 1 个配额）；中量级可读写 3 个 / 只读 5 个；重量级不额外限制。
2. **串行派发**：每个实施 Agent 及其评审 Agent 串行执行，严禁同时派发多个实施 Agent；前序输出不满足要求时的返工派发计入累计配额。
3. **并行写入不得使用本技能** — 确需并行时改用 `dispatching-parallel-agents`，且共享契约已冻结、写入路径互斥、运行环境隔离。
4. **子 Agent 约束**：不扩大范围、不修改共享契约、不自行集成、不继续派发；需要超出范围时只报告，由主 Agent 决定后续流程。
5. **Git 约束**：实施 Agent 可按 `git-development.md` 创建范围明确的普通本地提交，但不得 amend、改写历史或推送。

## 流程

1. **读取计划** — 读取实施计划，记录上下文与全局约束，创建待办（`update_plan`）。
2. **起飞前计划审查** — 扫描计划内冲突（任务间矛盾、与全局约束矛盾、评审标准会判定为缺陷的内容），打包成一个问题问用户；扫描干净则直接开始。
3. **逐任务执行** — 每个任务分派全新实现子智能体 → 处理四状态（DONE 生成审查包 / DONE_WITH_CONCERNS 先读疑虑 / NEEDS_CONTEXT 补上下文重派 / BLOCKED 评估阻塞原因）→ 分派任务审查者（规格合规 + 代码质量）→ 关键/重要问题派修复子智能体并重审 → 标记任务完成。
4. **结尾宽范围审查** — 全部任务完成后分派最终代码审查，按 `finishing-a-development-branch` 或 harness 收尾规则结束（不 push）。

## 连续执行

任务之间不向用户确认进度；唯一停下的理由是：无法解决的 BLOCKED、确实妨碍推进的歧义（打包提问）或全部任务完成。HITL 强制项除外。

## 红线

- 严禁同时派发多个实施 Agent。
- 不超出档位派发配额。
- 子 Agent 不扩大范围、不修改共享契约、不自行集成、不继续派发。
