# 测试驱动开发（Harness 裁剪版）

本技能是插件 `superpowers-zh:test-driven-development` 的 harness 门禁版。红-绿-重构完整细节可参考插件原版；**档位门禁与本文件为准**。

## 档位门禁

- **轻量级**：不强制 TDD。把唯一测试轮次用于信息量最高的验证，按以下顺序选择：现有端到端/集成测试 → 定向测试 → 构建/类型检查/lint；不得为了扩大覆盖临时拼接多个独立测试目标。
- **中量级**：高风险逻辑优先 TDD（红-绿-重构），其余按风险选择；测试轮次最多 3 轮。
- **重量级**：完整执行红-绿-重构循环，轮次不额外限制，仍受平台与不可绕过底线约束。
- 档位不明确时先按 `using-superpowers` 读取 `~/.codex/rules/workflow-policy.md` 定档位。

## 测试配额口径

- 测试轮次计入档位配额；一轮只能运行一个既有测试目标，允许框架内部执行多个用例，不得临时组合独立目标规避配额。
- 修复后重新运行计为新测试轮次；lint、类型检查、构建和测试框架执行计入测试轮次；`git diff`、只读搜索和纯静态内容检查不计入。
- 用户显式要求完整 TDD 时，放宽该循环必需的测试轮次并简短声明，不把整个任务提升为重量级；非核心文档、额外探索和一般性评审仍受原档位预算限制。

## 核心流程（红-绿-重构）

1. **红灯** — 写最小测试展示期望行为：一个行为、清晰名称、优先真实代码（除非不得已才用 mock）。
2. **验证红灯** — 运行并确认：测试失败（不是报错）、失败信息符合预期、失败原因是功能缺失而非拼写错误。
3. **绿灯** — 写最少代码让测试通过；不过度设计、不添加测试要求之外的功能。
4. **验证绿灯** — 运行确认通过、其他测试仍通过、输出干净；失败时修改代码而非测试。
5. **重构** — 仅在绿灯后清理：消除重复、改善命名、提取辅助函数；保持绿灯、不添加行为。
6. 为下一个行为重复。

## 好的测试

| 特质 | 好的 | 差的 |
|---|---|---|
| 最小化 | 只测一件事 | `test('validates email and domain and whitespace')` |
| 清晰 | 名称描述行为 | `test('test1')` |
| 展示意图 | 展示期望的 API | 掩盖代码本应做什么 |

## 例外（须询问用户）

一次性原型、生成的代码、配置文件。轻量级档位视为默认例外，按档位门禁处理。

## 红线

- 没有失败的测试就不写生产代码（仅适用于执行 TDD 的档位与场景）。
- 不得跳过红灯验证或绿灯验证。
- 不得以 TDD 为名突破档位测试配额，除非用户显式要求（见配额口径）。
