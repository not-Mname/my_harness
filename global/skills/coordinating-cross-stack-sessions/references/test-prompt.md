## 任务上下文

- 需求：{REQUIREMENT}
- 项目根目录：{PROJECT_ROOT}

- 契约摘要：{CONTRACT_SUMMARY}
- 客户端交付状态：{CLIENT_DELIVERY_STATUS}
- 服务端交付状态：{SERVER_DELIVERY_STATUS}

## 开始前

1. 将工作目录切换到 {TEST_WORKSPACE}。
2. 完整读取并遵循以下全部规则：
{APPLICABLE_AGENTS_FILES}
3. 上述清单同时包含工作区祖先链规则和编排层显式指定的测试角色规则。显式角色规则即使不在源码祖先目录中仍然适用；冲突按项目编排规则声明的优先级处理，未声明时停止并报告。
4. 继续检查当前工作区内是否存在更深层 `AGENTS.md`；发现后先读取再修改其范围内文件。
5. 确认当前工作区、契约文件、被测产物和授权路径存在；发现不一致时停止并报告。
6. 以共享契约和已确认验收条件为预期来源，不得根据当前实现降低或改写断言。

## 目标

{TEST_OBJECTIVES}

按风险覆盖契约、客户端、服务端、集成和端到端层级；明确每项测试的被测边界、测试数据、前置状态和清理方式。无法自动化的检查列为人工验证项并说明原因。

## 路径边界

- 允许写入：
{WRITABLE_PATHS}
- 只读：
{READ_ONLY_PATHS}
- 禁止：
{FORBIDDEN_PATHS_AND_ACTIONS}

不得修改客户端、服务端、共享契约或生成代码来让测试通过。发现缺陷时给出证据和归属建议，不得自行扩大范围。

## 测试矩阵

{TEST_MATRIX}

至少考虑成功、契约错误、鉴权、边界输入、重复请求、并发、超时、失败回滚和持久化一致性；不适用项需说明依据。

## 验收与验证

{TEST_ACCEPTANCE_CRITERIA}

执行：
{TEST_VERIFICATION_COMMANDS}

记录命令、退出状态和关键结果。测试环境或依赖未就绪时报告阻塞，不得伪造通过结果。

## 禁止事项

- 不发明或修改 API、数据结构、错误码、交互和数据行为。
- 不放宽断言、跳过失败用例或修改生产实现来迁就测试。
- 不自行集成其他角色的分支或改动。
- 不继续派发子任务。

## 完成 handoff

仅报告：
1. 变更文件
2. 使用的契约及版本
3. 测试矩阵覆盖情况
4. 验证命令和结果
5. 缺陷证据与归属建议
6. 风险
7. 剩余工作
