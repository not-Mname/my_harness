# 协调跨端多会话

## 核心原则

先冻结共享契约，再为客户端、服务端和测试生成自包含提示词。每个会话只消费已确认的契约和自身适用的 `AGENTS.md`，不得通过互相猜测完成协作。

本 Skill 只生成提示词和交接顺序，不创建会话、分支、worktree，不修改业务代码。

## 收集输入

生成提示词前，读取目标项目根目录 `AGENTS.md`，并沿三个目标路径分别读取全部祖先链 `AGENTS.md`。同时读取父级编排规则显式声明或用户指定的角色 `AGENTS.md`；角色规则可以独立存放，不得仅因它不在源码祖先链中就将其排除。不要把保存 harness 配置的目录当成目标业务工作区。

必须获得或从现有文件确认：

| 输入 | 要求 |
|---|---|
| 需求 | 明确目标、范围和用户可观察结果 |
| 项目根目录 | 真实业务项目的绝对路径 |
| 三个工作区 | 各会话的绝对路径；说明是否为独立 worktree |
| 规则来源 | 每个角色的祖先链规则，以及编排层显式指定的角色规则绝对路径 |
| 共享契约 | 文件绝对路径、已确认摘要和版本或状态 |
| 路径所有权 | 可写、只读和禁止路径 |
| 依赖状态 | mock、服务地址、测试数据及上游是否就绪 |
| 验收 | 每个角色的定向验证和最终端到端验证 |

需求目标、API、数据结构、交互、数据行为、安全或外部副作用不明确时，使用项目规定的 HITL Checkpoint，确认后再生成实施提示词。不要用占位符伪装成已冻结契约。

## 冻结协作边界

1. 指定契约的唯一维护者；客户端、服务端和测试默认只读契约。
2. 契约至少覆盖请求、响应、错误、鉴权、幂等、超时、兼容性及数据一致性。
3. 确认三个会话的写入路径互不重叠；重叠时改为串行或重新划分所有权。
4. 明确依赖顺序：契约先行，客户端与服务端可在边界冻结后并行，测试实现依赖可测试接口，最终联调串行进行。
5. 契约缺失或冲突时只输出阻塞项和契约负责人提示词，不输出允许自行补定字段的实施提示词。

## 生成角色提示词

按需读取并完整套用以下模板：

- 客户端：[references/client-prompt.md](references/client-prompt.md)
- 服务端：[references/server-prompt.md](references/server-prompt.md)
- 测试：[references/test-prompt.md](references/test-prompt.md)

用已确认事实替换模板变量；若某项不适用，明确写“无”，不要删除字段。每段提示词必须能在没有当前对话历史的独立会话中执行。

## 输出格式

依次输出：

1. `协作摘要`：契约、所有权、依赖图和集成顺序。
2. `CLIENT PROMPT`：完整客户端会话提示词。
3. `SERVER PROMPT`：完整服务端会话提示词。
4. `TEST PROMPT`：完整测试会话提示词。
5. `集成清单`：实际变更路径核对、契约一致性、定向测试和端到端验证。

不要创建仅引用“上文”“同前”或当前聊天内容的提示词。

## 质量门禁

交付前逐项确认：

- 三段提示词使用同一契约路径和摘要。
- 每段均含目标工作区、祖先链规则、显式角色规则、允许/只读/禁止路径、依赖、验收和 handoff。
- 不因显式角色规则位于源码路径之外而忽略它；提示词必须要求目标会话逐项读取列出的规则文件。
- 客户端不定义服务端字段；服务端不替客户端决定交互；测试不修改生产实现来迁就断言。
- 子会话不得扩大范围、修改共享契约、自行集成或继续派发。
- 最终验证由集成负责人执行，不能用三个角色的完成声明替代。

## 常见错误

| 错误 | 处理 |
|---|---|
| 把 harness 的规则源目录当成业务项目 | 要求真实项目根目录并解析绝对路径 |
| 只写“遵循 AGENTS.md” | 列出该角色实际适用的全部文件 |
| 只按源码祖先链发现规则 | 合并祖先链规则与编排层显式角色规则 |
| 客户端和服务端边做边定字段 | 暂停实施，先冻结共享契约 |
| 测试会话顺手修复生产代码 | 只报告失败和归属，交回对应角色 |
| 多会话共享同一工作树且写入重叠 | 使用独立 worktree 或改为串行 |
