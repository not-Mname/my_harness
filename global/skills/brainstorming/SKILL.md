# 头脑风暴（Harness 裁剪版）

本技能是插件 `superpowers-zh:brainstorming` 的 harness 门禁版。完整流程细节可参考插件原版；**档位门禁与本文件为准，冲突时以本文件为准**。

## 档位门禁

- **轻量级**：压缩为必要澄清 + 简短方案确认，不写 spec、不生成计划文档。一次消息内合并澄清，确认后立即实现。
- **中量级**：合并需求澄清、方案比较和关键设计确认，避免逐项往返；多文件、跨模块或存在关键契约时写 spec，多步骤任务生成可压缩实施计划。
- **重量级**：完整执行下方核心流程，含 spec 文档与用户书面审查。
- 档位不明确时先按 `using-superpowers` 读取 `~/.codex/rules/workflow-policy.md` 定档位。

## 冲突处理

- 插件原版 HARD-GATE 在本 harness 中改为：**未经用户确认设计不得进入实现**；轻量级/中量级以“用户确认”为门，不要求完整 spec。
- 澄清轮次服从档位配额（轻量 3 轮 / 中量 5 轮）；低影响假设标记 `[ASSUMED]` 可跳过澄清直接执行。
- 涉及需求目标、数据结构、API 契约、交互流程、性能指标、资源、项目设置、数据、安全或外部副作用时，不得假设，须进入 HITL Checkpoint（`[CP-n]`）。
- 本技能结束后只调用 `writing-plans`（重量级）或直接进入实现（轻/中量级），不调用其他实现技能。

## 核心流程（重量级完整版）

1. **探索项目上下文** — 检查文件、文档、最近的 commit。
2. **提出澄清问题** — 每次一个，理解目的/约束/成功标准；优先选择题；档位裁剪时合并提问。
3. **提出 2-3 种方案** — 附带权衡分析和推荐，先展示推荐方案并说明理由。
4. **分节展示设计** — 按复杂度分节，每节获得用户批准后再继续。
5. **编写设计文档** — 保存到 `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`。
6. **规格自检** — 检查占位符、内部一致性、范围、歧义，发现即内联修复。
7. **用户审查书面规格** — 批准后调用 `writing-plans` 创建实施计划。

## 核心原则

- 每次一个问题；优先选择题；严格 YAGNI；探索替代方案；增量验证；有歧义就回头澄清。
- 在现有代码库中：先探索现有结构、遵循现有模式，不提议无关重构。

## 验证

- 交付前确认：设计已获用户批准；spec（如生成）无占位符与矛盾；范围聚焦到可用一个实施计划覆盖。
