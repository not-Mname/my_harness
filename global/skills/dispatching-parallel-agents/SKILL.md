# 并行派发智能体（Harness 裁剪版）

本技能是插件 `superpowers-zh:dispatching-parallel-agents` 的 harness 门禁版。任务构造与汇合细节可参考插件原版；**配额与并行条件以本文件为准**。

## 派发前必读

派发前读取 `~/.codex/rules/workflow-policy.md` 与 `~/.codex/rules/multi-agent-assistance.md`，确认档位预算与协作规则。

## 门禁与配额

1. **档位配额**（单任务累计派发，含完成、失败、中断、返工）：轻量级可读写 1 个 / 只读 3 个；中量级可读写 3 个 / 只读 5 个；重量级不额外限制，仍受平台并发上限约束。
2. **身份冻结**：派发时冻结只读或可读写身份；只读 Agent 不得升级为可读写。
3. **子 Agent 不得继续派发**；不得自行集成、修改共享契约或扩大范围。
4. **并行独立条件**（全部满足才并行）：目标和输出可单独验收；输入、依赖及 API/类型契约已确定；执行顺序不影响结果；写入范围不重叠；不共享可变状态、运行环境或互斥资源。
5. **禁止并行**：后一任务依赖前一任务输出或多个现象同根因；修改同一文件、共享生成物或公共接口未定；Editor MCP 写入、场景或资源修改；数据迁移；Git 暂存、拉取、合并、提交等改变共享状态的操作；共用开发服务器、端口、数据库、缓存或构建目录；正在等待 HITL Checkpoint；派发成本高于直接处理。
6. **独立问题确认**：一个问题只有目标可单独验收、无依赖且顺序无关时才视为独立；不得为使用多 Agent 人为拆分任务。

## 流程

1. **识别独立的问题域** — 按故障或子系统分组，确认互不依赖。
2. **构造聚焦任务** — 每个 Agent 获得：明确范围、清晰目标、约束（不修改其他代码）、预期输出；输入确定、写入互斥、无共享可变状态的只读任务优先并行。
3. **并行派发** — 同一无依赖层内使用多个 `spawn_agent`；串行依赖则按层推进，不提前派发。
4. **审查与集成** — 汇合前比较实际变更路径、声明范围与用户授权范围，确认共享契约未被擅自修改；阅读总结、验证修复无冲突、执行整体验证、集成。发现重叠或新依赖立即停止相关并行写入，保留已完成结果并改为串行。

## 红线

- 不满足独立条件或命中禁止并行清单时，绝不并行派发。
- 不超出档位派发配额。
- 子 Agent 不继续派发、不自行集成、不扩大范围；越界需求只报告，由主 Agent 决定后续流程。
