# Workflow 模式使用指南

## 快速开始

新对话默认进入自动模式，无需手动设置：

```text
帮我修复登录超时问题
```

系统会先声明本任务采用的档位：

```text
[自动模式 -> 中量级] 涉及多文件行为修改，需要有限设计和回归验证。
```

自动判定只对当前任务生效，下一个任务会重新判断。

## 模式切换

### 自动模式

```text
$workflow-auto
```

或：

```text
[模式：自动]
```

适合大多数日常使用。每个任务分别选择轻量级、中量级或重量级，并允许在发现新风险后自动升级。

### 轻量级

```text
$workflow-light
```

或：

```text
[模式：轻量]
```

速度优先，适合只读查询、解释、翻译、局部文档修改，以及范围明确的低风险改动。

每个任务最多允许：

- 1 个可读写 Agent。
- 3 个只读 Agent。
- 1 轮测试。
- 3 轮澄清。

### 中量级

```text
$workflow-medium
```

或：

```text
[模式：中量]
```

速度与质量平衡，适合常规功能开发、一般 Bug 修复、边界清晰的多文件修改，以及需要有限设计、测试和评审的任务。

每个任务最多允许：

- 3 个可读写 Agent。
- 5 个只读 Agent。
- 3 轮测试。
- 5 轮澄清。

### 重量级

```text
$workflow-heavy
```

或：

```text
[模式：重量]
```

完整性优先，适合架构调整、跨模块重构、公共契约变更、安全与数据任务，以及明确要求完整 TDD、全面评审或最高可靠性的任务。

重量级不额外限制 Agent、测试和澄清次数，但仍受平台能力、安全规则和 HITL 约束。

## 携带任务切换

可以在切换模式的同时直接提交任务：

```text
$workflow-light 帮我修正 README 中的安装命令
```

系统会先切换到轻量级，再执行任务。

单独发送模式指令时，只切换模式：

```text
$workflow-medium
```

结果：

```text
已切换为持续中量级流程。
```

## 固定模式生命周期

手动切换到轻量级、中量级或重量级后，该模式会持续到用户再次手动切换模式或当前对话结束。

固定模式不会根据任务复杂度自动升级或降级。使用以下指令恢复自动判断：

```text
$workflow-auto
```

## 任务与预算

单次用户提示默认视为一个完整任务，共享一次模式判定和一组预算。

例如：

```text
修改登录页文案、修复接口超时，并补充测试
```

即使包含多个子目标，默认仍共享一组配额。

需要分别计数时，应明确要求独立交付和验收：

```text
请拆成三个独立任务，分别完成并验收：
1. 修改登录页文案
2. 修复接口超时
3. 补充测试
```

Agent 也可以通过 HITL 请求确认拆分。

## 测试轮次

一次测试轮次只能运行一个既有测试目标，例如一个测试文件、一个测试套件、一个项目测试脚本，或一次构建、类型检查及 lint。

修复后重新运行会消耗新的一轮。以下操作不计入测试轮次：

- `git diff`。
- 只读搜索。
- 纯静态内容检查。
- 因环境故障而未真正开始的验证。

不得临时拼接多个独立测试目标来规避配额。

轻量级只有一轮测试时，按以下顺序选择：

1. 能覆盖核心逻辑、主要边界和主要失败模式的现有端到端或集成测试。
2. 覆盖本次修改最关键路径的定向测试。
3. 最接近用户可观察结果的构建、类型检查或 lint。

## Agent 配额

Agent 数量按单个任务累计派发量计算，而不是同时活动数量。

以下情况均占用额度：

- Agent 正常完成。
- Agent 执行失败。
- Agent 被中断。
- 将返工交给同一或新的 Agent。

主 Agent 自行修正不占用派发额度。子 Agent 不得继续派发下级 Agent。

## 显式指定 Skill

用户显式指定 Skill 时，该要求高于模式预算。

例如：

```text
$workflow-light 使用 test-driven-development 完整修复这个 Bug
```

为了完成 TDD 的红、绿、重构循环，必要测试轮次和直接参与的 Agent 可以超过轻量级上限，但必须遵守以下边界：

- 只放宽完成 Skill 硬性步骤所需的最低配额。
- 超额使用仍需记录。
- 非核心文档、额外探索和一般性评审仍受轻量级限制。
- 不会因此把整个对话切换为重量级。

## 自动升级

只有自动模式可以在任务中途升级：

```text
[自动模式：轻量级 -> 中量级] 发现跨模块影响，需要第二轮必要测试。
```

允许轻量级升级到中量级，也允许轻量级或中量级升级到重量级。自动模式不得自动降级，已经使用的配额会计入升级后的档位。

## 不可绕过底线

任何模式都不能绕过：

- 法律、合规、安全和隐私要求。
- 生产数据、数据库破坏和不可逆迁移确认。
- 支付、发布、外部通信及其他不可逆副作用确认。
- Git 历史改写确认及项目明确规定的推送禁令。
- Cocos、Unity、资源、项目设置和 Editor MCP 高风险操作确认。
- 用户拒绝或尚未授予的 HITL 权限。
- 更高优先级规则要求的验证和授权。

固定模式与底线冲突时，系统会暂停：

```text
当前[轻量级]与[生产数据修改确认]冲突。
可选处理：切换至[重量级]、缩小任务范围或停止。
```

不能选择忽略底线。

## 推荐用法

日常任务使用自动模式：

```text
$workflow-auto
```

明确追求速度：

```text
$workflow-light 快速修正文档中的错误链接
```

常规开发：

```text
$workflow-medium 实现用户资料编辑功能
```

高风险任务或完整 Superpowers 流程：

```text
$workflow-heavy 重构鉴权模块，并完整执行 TDD 和代码评审
```

## 技能分级适配

不同档位会分级适配适用的 Superpowers 技能，避免“1% 必须调用”机制拖慢轻量级任务：

| 技能 | 轻量级 | 中量级 | 重量级 |
|---|---|---|---|
| brainstorming | 压缩为必要澄清+简短方案确认，不写 spec | 合并澄清+关键设计确认，spec 可选 | 完整流程+spec |
| test-driven-development | 不强制，测试轮给最高信息量验证 | 高风险逻辑优先 | 完整 TDD |
| using-git-worktrees | 默认禁止，须 HITL 授权 | 须 HITL 授权 | 须 HITL 授权 |
| dispatching-parallel-agents | 一般不派发，受配额约束 | 满足独立条件才并行 | 满足独立条件才并行 |
| subagent-driven-development | — | 按需，串行实现+评审 | 按需 |

路由与完整裁剪表见 superpowers-zh 插件的 `using-superpowers`（`~/.codex/plugins/local/superpowers-zh/skills/using-superpowers/SKILL.md`）；分级适配后的技能直接位于插件 `skills/` 目录，历史版本归档于 `~/.agents/skills/superpowers` 版本库。
