# Generate Handoff Skill 设计

## 目标

新增通用任务交接 Skill `generate-handoff`。用户显式输入 `$generate-handoff` 后，Skill 为下一位 AI Agent 生成可独立恢复当前工作的 Markdown 文档，使接手者无需依赖原聊天记录即可判断当前状态、验证证据、风险与下一步。

该 Skill 不生成 `coordination-core` 定义的跨角色 `handoff.yaml`，不负责恢复任务，也不执行交接文档中列出的剩余工作。

## 范围

### 包含

- 读取当前工作区、任务上下文与适用规则。
- 核对实际文件、Git 状态、当前会话决策与验证证据。
- 区分当前任务改动、用户已有改动和归属不明改动。
- 生成版本化 Markdown 交接文档。
- 在写入前后检查路径、内容完整性与事实一致性。
- 将验证通过的 Skill 同步到本机全局 Skill 目录。

### 不包含

- 自动检测任务暂停、上下文不足或会话结束。
- 未输入 `$generate-handoff` 时主动建议或生成交接文档。
- 为补齐证据而运行测试、构建或修改业务文件。
- 恢复任务、执行下一步或修改当前任务状态。
- 替代 `.harness/` 下的角色交付协议。

## Skill 布局

仓库规范源：

```text
global/skills/generate-handoff/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── assets/
    └── handoff-template.md
```

职责划分：

- `SKILL.md`：定义入口、参数、事实采集流程、真实性门禁、路径处理、失败策略和自检。
- `assets/handoff-template.md`：定义稳定的 Markdown 输出结构，不承载流程规则。
- `agents/openai.yaml`：提供 UI 元数据和以 `$generate-handoff` 开头的默认提示语。

实现时使用 `skill-creator` 的 `init_skill.py` 初始化目录，并使用 `quick_validate.py` 校验仓库副本与全局副本。

## 调用契约

唯一入口是用户显式输入 `$generate-handoff`。普通的“交接”“handoff”讨论不触发 Skill。

支持以下调用：

```text
$generate-handoff
$generate-handoff topic=workflow-budget
$generate-handoff path=docs/handoffs/custom-handoff.md
```

参数规则：

- `topic`：可选，必须规范化为小写连字符名称，用于默认文件名。
- `path`：可选，相对当前工作区的 Markdown 文件路径；用户显式路径优先于默认路径。
- 未提供 `topic` 时，从当前已确认任务目标生成明确的主题名称。
- 无法可靠推导主题时发布 HITL Checkpoint，不使用 `task`、`work` 等模糊名称。
- 显式路径解析后必须仍位于当前工作区；越界、绝对路径或非 Markdown 目标均停止生成并报告原因。

## 输出路径

未指定 `path` 时写入：

```text
docs/handoffs/YYYY-MM-DD-<topic>-handoff.md
```

默认目录不存在时允许创建 `docs/handoffs/`。同名文件已存在时依次使用 `-02`、`-03` 等后缀，禁止覆盖历史交接。

自定义目录不存在时，先读取输出路径沿途的 `AGENTS.md` 并按适用规则判断是否允许创建；需要用户决定时通过 HITL Checkpoint 暂停。

## 文档契约

生成的交接文档固定包含以下章节，空章节保留并明确写“无”。

### 元数据

- 生成时间与时区。
- 工作区绝对路径。
- 当前任务状态。
- 当前分支与 HEAD，仅 Git 工作区记录。
- 用户说明的交接原因；未说明时写“未提供”。

### 任务目标

- 原始目标。
- 当前验收标准。
- 明确不在范围内的事项。

### 必须遵守的规则

- 已读取且适用于后续工作的 `AGENTS.md`。
- 当前流程模式与适用 Skill。
- HITL、Git、Editor MCP 或其他强制门禁。

### 当前进展

- 已完成。
- 进行中。
- 尚未开始。

### 文件与变更

- 当前任务修改的文件及用途。
- 用户原有或来源不明的改动。
- 新增但未跟踪的文件。
- 不得覆盖或回退的内容。

### 关键决策

- 已确认决定及必要依据。
- 带依据的 `[ASSUMED]` 低影响假设。
- 已关闭与未关闭的 HITL Checkpoint。

### 验证证据

- 实际执行的命令。
- 对应退出码和关键结果。
- 未执行的验证及原因。

### 阻塞、风险与未知项

- 当前 blocker。
- 残余风险。
- 无法从现有事实确认的信息及建议确认方法。

### 下一步

- 按依赖顺序排列的可执行步骤。
- 每步涉及的路径。
- 每步完成判定与建议验证。

### 接手起点

- 下一位 Agent 首先应读取的文件。
- 第一条建议执行的只读命令。
- 禁止直接执行的动作。

## 事实采集流程

1. 确认当前工作区并读取根目录和输出路径沿途的全部 `AGENTS.md`。
2. 检查 `.codegraph/`；存在索引时按项目规则优先用于代码定位。
3. 涉及 Git 检查前读取适用的 Git 规则。
4. 从当前用户请求、已确认 Checkpoint、当前计划和实际文件提取任务目标与进度。
5. 读取 `git status --short`、任务相关 diff 和必要的近期提交；非 Git 工作区明确记录“无 Git 证据”。
6. 从当前会话中收集实际执行过的验证命令、退出码和关键结果，不为补齐交接而新增测试或构建。
7. 区分已验证事实、用户决定、低影响假设和未知项。
8. 解析最终输出路径，确认位于当前工作区且目标文件不存在。
9. 使用模板生成文档并检查必填章节、占位符、路径、证据与下一步依赖顺序。
10. 写入后重新读取文档，确认内容完整，再向用户报告绝对路径。

## 真实性门禁

- 未执行的测试不得写成通过。
- 无法确认归属的改动不得算作当前任务成果。
- 不依赖聊天记录中的完成声明代替实际文件或验证证据。
- 不复制大段聊天内容，只保留已确认决定及其必要依据。
- 命令、路径、Checkpoint、代码标识符和日志关键行保留原文。
- 低影响推断必须标记 `[ASSUMED]` 并说明依据。
- 目标、契约、数据、安全、项目设置或接手方向不明确时不得假设，必须通过 HITL Checkpoint 确认。
- 工作区中的无关改动只读记录，不修改、不暂存、不回退。

## 失败处理

| 场景 | 行为 |
|---|---|
| 缺少非关键事实 | 写入“未知”、影响和确认方法 |
| 缺少会改变接手方向的关键信息 | 发布 HITL Checkpoint 并暂停生成 |
| 非 Git 工作区 | 继续生成并明确缺少 Git 证据 |
| 输出路径越界或非法 | 停止，不创建文件 |
| 默认文件名冲突 | 使用递增数字后缀，不覆盖 |
| 自定义目录能否创建不明确 | 按适用规则发布 HITL Checkpoint |
| 写入或回读校验失败 | 保留错误原文，不宣称已生成 |

## 测试策略

Skill 按 `writing-skills` 的红、绿、重构流程验证。

### 红灯基线

在隔离的临时工作区中，让未加载 Skill 的 Agent 执行同类交接请求，逐字记录其行为和合理化依据。基线至少覆盖：

- 未执行测试却写成通过。
- 把预先存在的脏改动归到当前任务。
- 缺少明确下一步或禁止事项。
- 覆盖已有交接文件。
- 在关键信息缺失时自行猜测。

### 绿灯与重构

加载 `$generate-handoff` 后重跑相同场景，确认所有基线失败消失。再覆盖以下变体：

- 正常 Git 项目与非 Git 工作区。
- 用户已有修改和未跟踪文件。
- `topic` 与 `path` 参数。
- 输出路径越界。
- 同名文件冲突。
- 当前会话没有执行测试。
- 关键目标或接手方向不明确。

若 Agent 发现新的规避方式，将对应禁止项以最小规则补入 Skill，并重跑相关场景。

### 静态校验

- 使用 `quick_validate.py` 校验 Skill 目录。
- 检查 `SKILL.md` frontmatter 仅有 `name` 与 `description`。
- 检查 `description` 覆盖 `$generate-handoff` 的显式触发条件，且不鼓励自然语言隐式触发。
- 扫描模板中的未替换占位符、重复字段和模糊词。
- 检查 `agents/openai.yaml` 与 Skill 一致。

## 验收标准

一名未接触原会话的 Agent 只读取生成文档后，必须能准确回答：

1. 当前目标和完成状态是什么。
2. 哪些修改属于当前任务，哪些归属未知。
3. 哪些验证实际执行过。
4. 当前 blocker、风险和未决决定是什么。
5. 第一项可执行工作及其完成判定是什么。
6. 哪些操作不得直接执行。

同时满足：

- 无指令时不触发，输入 `$generate-handoff` 时可被发现。
- 输出文件位于约定路径且不覆盖历史文件。
- 未知信息可见，关键未知项不会被假设掩盖。
- Skill 目录通过静态校验和前向场景测试。

## 全局同步

仓库副本验证通过后，将以下目录同步到本机：

```text
global/skills/generate-handoff/ -> /Users/edy/.agents/skills/generate-handoff/
```

同步仅包含本任务创建的 Skill 文件，不修改仓库根目录文件或其他全局 Skill。逐文件使用 `cmp` 确认仓库副本与全局副本一致，并对全局副本再次运行 `quick_validate.py`。

## 实现边界

本设计可由一个实现计划覆盖：初始化 Skill、建立基线场景、编写最小流程与模板、执行前向测试、静态校验并同步全局目录。无需修改 `coordination-core`、Workflow 策略或项目级 `AGENTS.md`。
