# Workflow 策略歧义消除设计

## 目标

在不改变四档流程模式架构、不拆分规则文件的前提下，完善 `global/rules/workflow-policy.md` 的术语、计数边界、验证选择、显式 Skill 覆盖和不可绕过底线，使 Agent 能在复杂提示、多子目标、返工和固定模式冲突场景中得到唯一、闭环的执行结论。

## 范围

- 只修改 `global/rules/workflow-policy.md`。
- 不修改 `workflow-auto`、`workflow-light`、`workflow-medium` 或 `workflow-heavy`。
- 不拆分 rule 或创建新 Skill。
- 不读取、修改或提交当前未跟踪的 `global/skills/coordination-manual/`。
- 仓库验证通过后，将策略同步到 `/Users/edy/.codex/rules/workflow-policy.md`。

## 术语与生命周期

在“使用方式”之后新增“术语定义”：

- **任务**：单次用户提示要求的完整交付单元，共享一次模式判定和一组 Agent、测试及澄清预算。
- **子任务**：Agent 为完成任务而拆出的内部工作项，不重置任务预算。
- 一次提示包含多个独立子目标时，默认仍属于一个任务。只有用户明确要求分别交付、分别验收，或 Agent 通过 HITL 获得拆分确认后，才建立多个独立任务并分别计数。
- **对话生命周期**：手动固定模式持续到用户再次切换或当前对话结束；新对话默认进入自动模式。
- **返工派发**：前序 Agent 输出不满足要求而进行的任何修正性派发，无论对象是同一还是新的子 Agent。主 Agent 自行完成的修正不计入派发额度。

该定义防止通过在单次提示中罗列子目标来重复获得预算，同时保留真正独立交付任务的显式拆分能力。

## 轻量级验证选择

将“信息量最高的验证”落实为有序决策：

1. 优先选择能覆盖核心逻辑、主要边界和主要失败模式的现有端到端或集成测试。
2. 不具备上述测试时，选择覆盖本次修改最关键路径的定向测试。
3. 仍无合适测试时，选择最接近用户可观察结果的构建、类型检查或 lint。
4. 不允许为了扩大覆盖而临时拼接多个原本独立的测试目标。

该顺序只指导如何使用既有的一轮测试预算，不改变现有测试轮次计数规则。

## 显式 Skill 与预算

用户显式指定 Skill 时，继续遵循“用户当前任务的明确要求高于模式预算”，但放宽规则收紧为：

- 只放宽完成该 Skill 硬性步骤所需的最低配额。
- 超出原上限的 Agent、测试和澄清仍记录实际使用量，只是不受当前档位上限阻断。
- 显式要求完整 TDD 时，红、绿、重构循环所必需的测试轮次，以及直接参与该循环的 Agent 可以超过原上限。
- 非核心文档、额外探索和一般性评审仍受原模式预算限制。
- 不得借显式 Skill 将整个任务无条件提升为重量级。

“直接相关”据此由 Skill 的硬性步骤与完成条件界定，而不是由 Agent 名称、目录或主观重要性界定。

## 术语统一

预算矩阵及重量级说明中的 “Harness 不限制” 统一改为“本模式不额外限制”。其中：

- **本模式**：当前 Workflow 档位施加的流程预算。
- **平台**：Codex 或宿主环境提供的并发、上下文和工具能力限制。
- **系统规则**：优先于项目与 Skill 的上层指令。

三者不得混用。“本模式不额外限制”不表示可以突破平台限制或系统规则。

## 不可绕过底线

在规则优先级之后集中增加非穷尽清单：

- 法律、合规、安全、隐私和敏感数据要求。
- 生产数据、数据库破坏和不可逆迁移确认。
- 支付、发布、外部通信及其他不可逆副作用确认。
- Git 历史改写所需确认，以及项目明确禁止的推送或强制推送。
- Cocos、Unity 场景、资源、项目设置和 Editor MCP 高风险操作确认。
- 用户拒绝或尚未授予的 HITL 权限。
- 更高优先级指令明确要求的验证与授权。

该清单用于汇总现有分散规则，不取代更具体的全局或项目规则，也不视为穷尽列举。

## 固定模式冲突闭环

固定模式预算与不可绕过底线冲突时，Agent 不得自动升级，也不得提供忽略底线的选项。必须暂停并明确报告：

```text
当前[模式]与[具体不可绕过规则]冲突。可选处理：切换至[所需模式]、缩小任务范围或停止。
```

用户选择切换时，按模式切换规则继续；选择缩小范围时，只执行不触碰冲突的范围；选择停止时保留已有安全结果并结束。用户没有明确选择前不得继续产生受限制的修改或外部副作用。

## 文件修改

在 `global/rules/workflow-policy.md` 中执行以下定向编辑：

1. 在“使用方式”后增加“术语定义”。
2. 将预算矩阵和重量级说明中的 Harness 表述改为“本模式不额外限制”。
3. 在轻量级流程裁剪中补充验证选择顺序。
4. 在 Agent 计数中补充返工派发定义。
5. 扩展显式 Skill 的最低必要放宽规则及 TDD 示例。
6. 在规则优先级后新增不可绕过底线清单。
7. 扩展异常处理中的固定模式冲突模板和三种闭环结果。

## 验证

1. 检查“任务”“子任务”“返工派发”和“对话生命周期”均有唯一明确定义。
2. 检查单提示多目标默认共享预算，显式或 HITL 拆分后才重置预算。
3. 检查轻量级验证存在端到端或集成、定向测试、构建或静态检查的有序回退。
4. 检查显式 Skill 仅获得硬性步骤所需的最低放宽，超额使用仍可审计。
5. 检查文档不存在 `Harness 不限制`，并清楚区分本模式、平台和系统规则。
6. 检查不可绕过底线清单存在，且固定模式冲突不提供忽略底线选项。
7. 检查 `git diff --check` 通过，且 diff 只包含策略文件和本设计流程产生的文档。
8. 同步后使用 `cmp` 确认仓库策略与本机全局策略逐字节一致。

## 风险

- 术语定义过宽会允许预算重置，过窄会阻碍真正独立交付；本设计采用“单提示默认一个任务，显式确认后拆分”作为可审计边界。
- 显式 Skill 放宽若按 Agent 角色判断，容易被滥用；本设计按 Skill 硬性步骤和最低完成条件判断。
- 不可绕过底线如果允许用户临时忽略，将破坏其定义；因此冲突选项只包含切换模式、缩小范围或停止。
